Quan hệ đa hình: một bình luận thuộc về bài viết hoặc món

Nếu bạn bỏ qua chặng 7 (view) thì không sao: chặng này chỉ dùng FK, CHECK và index từ chặng 3–5.

Mục tiêu: so ba cách lưu "bình luận thuộc về bài viết hoặc sản phẩm", đếm bình luận mồ côi của từng cách sau khi xóa bài viết #1, và chọn được cách để dùng với Prisma.

LÀ GÌ?
Quan hệ đa hình (polymorphic): một dòng con có thể trỏ tới một trong nhiều bảng cha. Ví dụ ở chuỗi F&B: bình luận cho bài khuyến mãi hoặc cho một món.
TẠI SAO?
Cách hay gặp nhất (cột commentable_type + commentable_id, kiểu Rails/Laravel) không thể khai báo FK. DB không còn giữ được toàn vẹn, và lỗi chỉ lộ ra khi đếm mồ côi.
KHI NÀO KHÔNG?
Khi chỉ có một loại cha thì dùng một FK thường. Khi số loại cha lớn và đổi liên tục (log, audit) thì type + id chấp nhận được, miễn là bạn có job đếm mồ côi.

Cách 1 · type + id: không có FK

commentable_id trỏ tới bảng nào là do cột commentable_type quyết định. FK chỉ trỏ được tới một bảng cố định, nên không có REFERENCES nào khai báo được.

-- #region typeid · Cách 1: commentable_type + commentable_id — không thể khai báo FK

);

Làm mẫu · cách 2 exclusive arc
  1. Mỗi loại cha một cột FK riêng, cho phép NULL: post_id REFERENCES poly_posts, product_id REFERENCES poly_products. Giờ DB kiểm được cả hai.
  2. CHECK (num_nonnulls(post_id, product_id) = 1): num_nonnulls đếm số tham số khác NULL. Bằng 1 nghĩa là thuộc về đúng một cha: không thể "không thuộc về ai", cũng không thể thuộc về cả hai.
  3. ON DELETE CASCADE: xóa bài 1 thì bình luận của bài 1 đi theo. Muốn giữ bình luận thì đổi thành RESTRICT để DB chặn việc xóa.
  4. Hai partial index WHERE post_id IS NOT NULL: index chỉ chứa các dòng có cha loại đó, nhỏ hơn index đầy đủ, và vẫn phục vụ kiểm tra FK khi xóa cha (chặng 3).
  5. Chạy region arc: mồ côi = 0, câu cuối chèn bình luận không có cha nhận 23514.
-- #region arc · Cách 2: exclusive arc — mỗi loại cha một cột FK cho phép NULL, CHECK đúng một cột có giá trị
SET search_path = lab07_modeling;  -- DB mặc định trỏ vào lab03_indexing
SET statement_timeout = '60s'; SET lock_timeout = '5s';
INSERT INTO poly_posts VALUES (1, 'Khai trương chi nhánh Q7') ON CONFLICT DO NOTHING;
DROP TABLE IF EXISTS poly_comments_arc;
CREATE TABLE poly_comments_arc (
  id         int GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  post_id    int REFERENCES poly_posts (id) ON DELETE CASCADE,
  product_id int REFERENCES poly_products (id) ON DELETE CASCADE,
  body       text NOT NULL,
  CHECK (num_nonnulls(post_id, product_id) = 1)   -- thuộc về đúng MỘT cha
);
CREATE INDEX ON poly_comments_arc (post_id) WHERE post_id IS NOT NULL;
CREATE INDEX ON poly_comments_arc (product_id) WHERE product_id IS NOT NULL;
INSERT INTO poly_comments_arc (post_id, product_id, body) VALUES (1, NULL, 'Chúc mừng!'), (NULL, 1, 'Ngon');
DELETE FROM poly_posts WHERE id = 1;   -- bình luận của bài 1 bị xóa theo (ON DELETE CASCADE)
SELECT count(*) AS orphans FROM poly_comments_arc c
WHERE (c.post_id IS NOT NULL AND NOT EXISTS (SELECT 1 FROM poly_posts p WHERE p.id = c.post_id))
   OR (c.product_id IS NOT NULL AND NOT EXISTS (SELECT 1 FROM poly_products p WHERE p.id = c.product_id));
INSERT INTO poly_comments_arc (post_id, product_id, body) VALUES (NULL, NULL, 'Không thuộc về ai');
-- #endregion

Cách 3 · mỗi loại cha một bảng bình luận

poly_post_comments và poly_product_comments, mỗi bảng một FK NOT NULL. Ghi sai loại là điều không thể xảy ra, vì không có cột loại. Cần "mọi bình luận" thì UNION ALL.

-- #region join · Cách 3: mỗi loại cha một bảng bình luận riêng, FK đầy đủ; gộp lại bằng UNION ALL khi cần
SET search_path = lab07_modeling;  -- DB mặc định trỏ vào lab03_indexing
SET statement_timeout = '60s'; SET lock_timeout = '5s';
INSERT INTO poly_posts VALUES (1, 'Khai trương chi nhánh Q7') ON CONFLICT DO NOTHING;
DROP TABLE IF EXISTS poly_post_comments, poly_product_comments;
CREATE TABLE poly_post_comments (
  id int GENERATED ALWAYS AS IDENTITY PRIMARY KEY, post_id int NOT NULL REFERENCES poly_posts (id) ON DELETE CASCADE, body text NOT NULL);
CREATE TABLE poly_product_comments (
  id int GENERATED ALWAYS AS IDENTITY PRIMARY KEY, product_id int NOT NULL REFERENCES poly_products (id) ON DELETE CASCADE, body text NOT NULL);
CREATE INDEX ON poly_post_comments (post_id);
CREATE INDEX ON poly_product_comments (product_id);
INSERT INTO poly_post_comments (post_id, body) VALUES (1, 'Chúc mừng!');
INSERT INTO poly_product_comments (product_id, body) VALUES (1, 'Ngon'), (2, 'Mặn mà');
SELECT 'Post' AS loai, post_id AS cha_id, body FROM poly_post_comments
UNION ALL
SELECT 'Product', product_id, body FROM poly_product_comments ORDER BY 1, 2;
DELETE FROM poly_posts WHERE id = 1;
SELECT (SELECT count(*) FROM poly_post_comments c WHERE NOT EXISTS (SELECT 1 FROM poly_posts p WHERE p.id = c.post_id))
     + (SELECT count(*) FROM poly_product_comments c WHERE NOT EXISTS (SELECT 1 FROM poly_products p WHERE p.id = c.product_id)) AS orphans;
-- #endregion

Prisma 7.9 · bạn dùng ở qlhd

Prisma không có quan hệ đa hình: một relation field chỉ trỏ tới một model (danh sách attribute trong Prisma schema reference không có polymorphic, không có CHECK · runs/prisma-claims.txt P8).

  • Arc = hai relation tùy chọn trên cùng model: postId Int? + post Post? @relation(fields: [postId], references: [id], onDelete: Cascade), tương tự productId/product. Prisma Client đọc include: { post: true, product: true } bình thường.
  • Dòng CHECK (num_nonnulls(post_id, product_id) = 1) không ghi được trong schema.prisma: chạy prisma migrate dev --create-only, thêm CHECK vào migration.sql, rồi mới apply. Hai partial index thì Prisma 7.4+ khai báo được bằng @@index(…, where: …) sau khi bật preview feature partialIndexes; chưa bật preview thì viết tay trong migration.sql.
  • Bảng riêng = hai model PostComment, ProductComment, mỗi model một relation bắt buộc. Không cần SQL tay.
  • Kiểu type + id trong Prisma chỉ là hai cột vô hướng commentableType String, commentableId Int: không relation, không include, app tự JOIN.
Tự làm · chặng 8

Đề: file đính kèm (ảnh hợp đồng, ảnh mặt tiền cửa hàng) thuộc về một hợp đồng hoặc một cửa hàng. Tạo 2 bảng cha nhỏ my_c8_contracts (id int PK, code text), my_c8_stores (id int PK, name text), mỗi bảng 2 dòng, rồi thiết kế my_attachments theo exclusive arc. Dùng tên my_* để file setup không xóa bảng của bạn.

PASS khi (chạy trong DBX, mỗi câu lỗi cố ý chạy riêng):

  • Đính kèm không có cha → 23514; có cả hai cha → 23514.
  • contract_id = 999 (không tồn tại) → 23503.
  • Xóa hợp đồng 1 → câu đếm mồ côi bên dưới trả 0.
  • Có 2 partial index, và câu tự kiểm tra thấy 1 CHECK + 2 FK.

SET search_path = lab07_modeling;
CREATE TABLE my_c8_contracts (id int PRIMARY KEY, code text NOT NULL);
CREATE TABLE my_c8_stores    (id int PRIMARY KEY, name text NOT NULL);
