## Edge cases from scouting

- The ledger race leaves extra transfers. That is harmless here: the current store balance is 45000, so `refund(2)` passes C12. But if Đạt runs only the `unordered` race and skips `ordered`, the store sits at 44500 and `refund(2)` gets 23514. The answer text already calls that "đúng hành vi", but PASS criterion 1 would then fail.
- `ledger_check_balanced` fires only `AFTER INSERT`, so an `UPDATE ledger_entries SET amount = …` bypasses the invariant. That is acceptable for an append-only ledger, but the guide never says the ledger must be append-only.
