LÀ GÌ?

TẠI SAO?

KHI NÀO KHÔNG?
Đừng chép lời giải khi yêu cầu khác: lọc theo tag là chính thì bảng nối; đếm chính xác từng click thì không dùng số ước lượng.

Slide 28 · Cần sửa
Slide nói

Thứ tự mới = (trên + dưới) / 2. Khi hết chỗ giữa 1000 và 1001 thì "dùng float".

PG 16 đo được

Float chỉ hoãn vấn đề. Cứ chèn vào ngay sau "TV": số nguyên hết chỗ sau 9 lần, float8 sau 53 lần, float4 sau 24 lần. Lời giải đủ: khi khoảng trống cạn thì đánh số lại cả danh sách bằng một câu, UPDATE 5.

-- #region ordering · Cột thứ tự có khoảng trống: chèn giữa = (trên + dưới) / 2. Chèn được bao nhiêu lần? (slide 28)
SET search_path = lab07_modeling;  -- DB mặc định trỏ vào lab03_indexing
SET statement_timeout = '60s'; SET lock_timeout = '5s';
DROP TABLE IF EXISTS cs_tasks;
CREATE TABLE cs_tasks (id int PRIMARY KEY, name text NOT NULL, pos float8 NOT NULL);
INSERT INTO cs_tasks VALUES (1, 'TV', 1000), (4, 'Working', 1500), (2, 'Commuting', 2000), (3, 'Gaming', 3000);
INSERT INTO cs_tasks VALUES (5, 'Cafe', (1000 + 1500) / 2.0);        -- kéo "Cafe" vào giữa TV và Working
SELECT name, pos FROM cs_tasks ORDER BY pos;
-- Người dùng cứ kéo việc mới vào ngay sau "TV": khoảng trống chia đôi mãi. Đếm số lần chia được trước khi hết chỗ.
WITH RECURSIVE
  i(n, lo, hi) AS (SELECT 0, 1000::bigint, 2000::bigint UNION ALL SELECT n + 1, lo, (lo + hi) / 2 FROM i WHERE (lo + hi) / 2 NOT IN (lo, hi)),
  d(n, lo, hi) AS (SELECT 0, 1000::float8, 2000::float8 UNION ALL SELECT n + 1, lo, (lo + hi) / 2 FROM d WHERE (lo + hi) / 2 NOT IN (lo, hi)),
  f(n, lo, hi) AS (SELECT 0, 1000::float4, 2000::float4 UNION ALL SELECT n + 1, lo, ((lo + hi) / 2)::float4 FROM f WHERE ((lo + hi) / 2)::float4 NOT IN (lo, hi))
SELECT (SELECT max(n) FROM i) AS so_lan_int, (SELECT max(n) FROM d) AS so_lan_float8, (SELECT max(n) FROM f) AS so_lan_float4;
-- Cách sửa: khi khoảng trống cạn, đánh số lại cả danh sách bằng MỘT câu lệnh.
UPDATE cs_tasks t SET pos = r.rn * 1000 FROM (SELECT id, row_number() OVER (ORDER BY pos) AS rn FROM cs_tasks) r WHERE r.id = t.id;
SELECT name, pos FROM cs_tasks ORDER BY pos;
-- #endregion

Slide 29–30 · Đúng trên PG16
Slide nói

Mỗi căn sinh trước 365 dòng (một năm), mỗi ngày một giá và một trạng thái.

PG 16 đo được

3 căn sinh INSERT 0 1095. Đổi giá ngày lễ: UPDATE 1. Đặt 3 đêm: UPDATE 3. Khách sau trùng một đêm chỉ sửa được 1/2 dòng, app ROLLBACK.

Làm mẫu · đặt phòng không bán trùng bằng một câu UPDATE
  1. Ý tưởng: không "SELECT kiểm tra rồi UPDATE" (hai bước, có race như chặng 3). Gộp kiểm tra vào WHERE status = 'OPEN'.
  2. Khách đặt 20→23/11 là 3 đêm. App biết trước phải sửa đúng 3 dòng. DB trả UPDATE 3 → COMMIT.
  3. Khách khác đặt 22→24/11 (2 đêm). Đêm 22 đã BOOKED nên chỉ còn UPDATE 1. 1 ≠ 2 → ROLLBACK. Đêm 23 vẫn OPEN, không ai bị bán dở.
  4. Hai khách bấm cùng lúc thì sao? UPDATE khóa từng dòng nó sửa (Bài 14 chặng 2). Người sau chờ, đọc lại status mới, rồi được số dòng nhỏ hơn.
  5. Cách thứ hai: lưu khoảng ngày daterange và để EXCLUDE cấm chồng lấn. Lỗi 23P01 đến từ DB, app không thể quên kiểm tra.

BEGIN;
UPDATE cs_availability SET status = 'BOOKED'
WHERE homestay_id = 1 AND day >= '2026-11-20' AND day < '2026-11-23' AND status = 'OPEN';
COMMIT;

BEGIN;
UPDATE cs_availability SET status = 'BOOKED'
WHERE homestay_id = 1 AND day >= '2026-11-22' AND day < '2026-11-24' AND status = 'OPEN';
ROLLBACK;
SELECT day, price, status FROM cs_availability WHERE homestay_id = 1 AND day BETWEEN '2026-11-19' AND '2026-11-24' ORDER BY day;

Tự làm · chặng 6

Đề: quán có 20 bàn. Thiết kế my_table_reservations (bàn, tên khách, số người, khoảng giờ tstzrange) sao cho DB cấm hai lượt đặt cùng bàn chồng giờ. Chứng minh bằng 3 câu INSERT: bàn 5 lúc 18:00–20:00 (được), bàn 5 lúc 19:00–21:00 (bị chặn), bàn 5 lúc 20:00–22:00 (được, vì khoảng [) không tính đầu cuối).

PASS khi: câu chồng giờ báo 23P01; câu tự kiểm dưới đây ra 1 dòng ràng buộc loại x và 0 cặp chồng nhau.

SET search_path = lab07_modeling;
SELECT conname, contype FROM pg_constraint
WHERE conrelid = 'lab07_modeling.my_table_reservations'::regclass AND contype = 'x';
SELECT count(*) AS so_cap_chong_nhau
FROM my_table_reservations a JOIN my_table_reservations b
  ON a.table_no = b.table_no AND a.id < b.id AND a.during && b.during;
Lời giải mẫu
SET search_path = lab07_modeling;   -- btree_gist nằm trong schema này
DROP TABLE IF EXISTS my_table_reservations;
CREATE TABLE my_table_reservations (
  id         int GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  table_no   int NOT NULL CHECK (table_no BETWEEN 1 AND 20),
  guest      text NOT NULL,
  party_size int NOT NULL CHECK (party_size > 0),
  during     tstzrange NOT NULL,
  EXCLUDE USING gist (table_no WITH =, during WITH &&)
);
