Nối dây trong Nest (chưa chạy trong lab này, kiểm chứng ở Pha B)

// modules/wallets/wallets.module.ts: nơi duy nhất biết Prisma nối với port
providers: [
  { provide: WALLET_REPOSITORY, useClass: PrismaWalletRepository },
  {
    provide: TransferFunds,
    useFactory: (repo: WalletRepository) => new TransferFunds(repo, randomUUID),
    inject: [WALLET_REPOSITORY],
  },
],

Đánh đổi: dùng useFactory thì use case không cần @Injectable(), 0 vi phạm nhưng thêm vài dòng module. Dùng @Injectable() + @Inject(TOKEN) ở application thì ngắn hơn, nhưng application phải import @nestjs/common. Slide 17 gọi đó là "violating the rules by using frameworks". Nhiều team chấp nhận điều này. Tài liệu kiến trúc đang để ngỏ quyết định này cho bạn, ghi vào ADR-008 sau khi làm xong. Domain thì giữ sạch trong cả hai cách.

Dòng code này về đâu?

  1. Quyết định đúng sai về nghiệp vụ, không có I/O: domain.
  2. Sắp thứ tự các bước, mở transaction qua port, kiểm tìm đủ dữ liệu: application.
  3. Có tên công nghệ (Prisma, FOR UPDATE, Redis): infrastructure.
  4. Có HTTP (status, ConflictException, decorator route): presentation.
  5. Chọn adapter nào: module, tức nơi nối dây.

Mùi cần nhận ra khi review

  • Entity có save(), hoặc domain có import gói ngoài.
  • Use case có if so sánh số liệu nghiệp vụ.
  • Controller trả Entity, hoặc import thẳng repository.
  • Interface chỉ có đúng một cài đặt và chép nguyên chữ ký của ORM: port đang không trừu tượng được gì.
  • Test chỉ chạy trên adapter RAM mà không có ca đồng thời trên DB thật.
