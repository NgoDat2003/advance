Từ yêu cầu tới ERD: entity, quan hệ, 4 loại bảng

Mục tiêu: đi đúng 3 bước của slide 5 cho một nghiệp vụ nhỏ của OmniPOS (đơn hàng + thanh toán), dựng nó thành 2 bảng thật, đọc ngược ERD từ catalog của PG, rồi xếp bảng vào 4 loại của slide 8.

LÀ GÌ?
Data modeling là biến danh sách field thô thành bảng, khóa và quan hệ. ERD là bản vẽ của kết quả đó.
TẠI SAO?
Code đổi hằng tuần, còn bảng đã có dữ liệu thì đổi rất đắt (chặng 4 đo cái giá của ALTER). Thiết kế sai từ đầu là món nợ trả lâu nhất.
KHI NÀO KHÔNG?
Đừng vẽ ERD 40 bảng trước khi biết use case và các câu query chính. Bắt đầu từ access pattern, vẽ đủ cho phần đang làm.

Làm mẫu · OmniPOS: đơn hàng và thanh toán
  1. Analysis. Use case: khách tạo đơn rồi thanh toán; khách ủng hộ (donate) mà không mua gì. Access pattern: tra đơn theo mã, xem các khoản thanh toán của một đơn. Field thô: mã đơn, trạng thái đơn, tổng tiền, loại giao dịch, số tiền, trạng thái giao dịch, thời điểm tạo.
  2. Data modeling. Gom field theo "thứ gì có vòng đời riêng": đơn hàng (NEW → PAID / CANCELLED) và giao dịch (PENDING → SUCCESS / FAILED). Hai entity, khóa chính bigint identity, nối bằng order_id nằm ở bảng giao dịch (lý do ở slide 12, chặng 3).
  3. Data integrity. Mỗi luật nghiệp vụ thành một ràng buộc: CHECK cho trạng thái, total >= 0, "đơn thì có order_id, donate thì không", và index cho cột order_id.

Mở labs/lesson-07-data-modeling/01-design-erd.sql trong DBX (tab ADVANCE_BE_LAB), bôi đen region erd → Run Selection.

-- #region erd · Hai entity Order và Payment theo table template (slide 7, 12, 20)
SET search_path = lab07_modeling;  -- DB mặc định trỏ vào lab03_indexing
SET statement_timeout = '60s'; SET lock_timeout = '5s';
DROP TABLE IF EXISTS erd_payment_transactions, erd_orders;
-- Entity "đơn hàng": có id, trạng thái (vòng đời) và cột kỹ thuật.
CREATE TABLE erd_orders (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  code        text NOT NULL UNIQUE,
  status      text NOT NULL DEFAULT 'NEW' CHECK (status IN ('NEW', 'PAID', 'CANCELLED')),
  total       numeric(14,2) NOT NULL CHECK (total >= 0),
  version     int NOT NULL DEFAULT 0,
  created_at  timestamptz NOT NULL DEFAULT now(),
  updated_at  timestamptz NOT NULL DEFAULT now()
);
-- Entity "giao dịch thanh toán": sinh ra SAU đơn hàng nên giữ cột tham chiếu order_id (slide 12).
-- order_id được phép NULL vì giao dịch ủng hộ (donate) không có đơn hàng.
CREATE TABLE erd_payment_transactions (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  kind        text NOT NULL CHECK (kind IN ('ORDER', 'DONATE')),
  order_id    bigint REFERENCES erd_orders (id),
  amount      numeric(14,2) NOT NULL CHECK (amount > 0),
  status      text NOT NULL DEFAULT 'PENDING' CHECK (status IN ('PENDING', 'SUCCESS', 'FAILED')),
  version     int NOT NULL DEFAULT 0,
  created_at  timestamptz NOT NULL DEFAULT now(),
  updated_at  timestamptz NOT NULL DEFAULT now(),
  CHECK ((kind = 'ORDER') = (order_id IS NOT NULL))   -- thanh toán đơn thì phải có order_id, donate thì không
);
CREATE INDEX ON erd_payment_transactions (order_id);  -- PG không tự tạo index cho cột FK (chặng 3)
-- #endregion

Bây giờ đọc ngược lại: ERD không chỉ nằm trên giấy, PG lưu nó trong catalog. Region catalog liệt kê cột của 2 bảng và mọi khóa ngoại giữa chúng.

-- #region catalog · Đọc ERD ngược từ catalog: bảng, cột, khóa ngoại (slide 7)
SET search_path = lab07_modeling;  -- DB mặc định trỏ vào lab03_indexing
SET statement_timeout = '60s'; SET lock_timeout = '5s';
SELECT c.relname AS bang, a.attname AS cot, format_type(a.atttypid, a.atttypmod) AS kieu, NOT a.attnotnull AS cho_phep_null
FROM pg_class c JOIN pg_attribute a ON a.attrelid = c.oid AND a.attnum > 0 AND NOT a.attisdropped
WHERE c.relnamespace = 'lab07_modeling'::regnamespace AND c.relname IN ('erd_orders', 'erd_payment_transactions')
ORDER BY c.relname DESC, a.attnum;
SELECT conrelid::regclass AS bang_con, confrelid::regclass AS bang_cha, pg_get_constraintdef(oid) AS dinh_nghia
FROM pg_constraint
WHERE contype = 'f' AND connamespace = 'lab07_modeling'::regnamespace AND conrelid::regclass::text LIKE 'erd_%';
-- #endregion

Hai điều cần thấy: order_id là cột duy nhất có cho_phep_null = t (để chỗ cho khoản donate), và catalog trả đúng một cạnh của ERD: FOREIGN KEY (order_id) REFERENCES erd_orders(id). Khi vào một dự án lạ, hai câu này cho bạn ERD thật nhanh hơn mọi tài liệu cũ.

Entity là đối tượng có identity và vòng đời (status). ERD minh họa quan hệ giữa các entity.

Đúng. Trong bảng thật, identity là khóa chính, vòng đời là cột status có CHECK. Hình thoi của ERD thành khóa ngoại, và catalog trả lại đúng (1 row) cho quan hệ đơn → thanh toán.

Tự kiểm (chưa lộ đáp án):

SET search_path = lab07_modeling;  -- DB mặc định trỏ vào lab03_indexing
CREATE TABLE IF NOT EXISTS my_table_types (
  bang  text PRIMARY KEY,
  loai  text NOT NULL CHECK (loai IN ('entity', 'relation', 'support', 'config')),
  ly_do text NOT NULL
);
-- INSERT INTO my_table_types VALUES ('stores', '…', '…'), … ;   -- 8 dòng của bạn
SELECT loai, count(*) AS so_bang, string_agg(bang, ', ' ORDER BY bang) AS cac_bang
FROM my_table_types GROUP BY loai ORDER BY loai;
Đáp án và câu so sánh
  • entity: stores, orders, menu_items — mỗi cái có id và vòng đời riêng.
  • relation: order_items (orders N–M menu_items), store_menu_items (stores N–M menu_items). Relation được phép có cột riêng như số lượng, giá.
  • support: store_opening_hours — chỉ có nghĩa khi gắn với một cửa hàng, không có vòng đời riêng.
  • config: payment_methods, provinces — danh mục ít đổi, nhiều nơi tham chiếu, rất hợp để cache.

Tranh luận hay gặp: order_items có thể coi là support của orders (dòng món sinh và chết cùng đơn). Chấp nhận nếu lý do của bạn nói rõ điều đó; điểm quan trọng là nó nối hai entity.

SELECT d.bang, m.loai AS ban_chon, d.loai AS dap_an, CASE WHEN m.loai = d.loai THEN '✔' ELSE '✘' END AS ket_qua
FROM (VALUES ('stores', 'entity'), ('orders', 'entity'), ('menu_items', 'entity'),
             ('order_items', 'relation'), ('store_menu_items', 'relation'),
             ('store_opening_hours', 'support'), ('payment_methods', 'config'), ('provinces', 'config')) d (bang, loai)
LEFT JOIN lab07_modeling.my_table_types m USING (bang) ORDER BY d.bang;
