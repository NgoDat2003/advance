Nó là gì

Một CLI Python chạy local, đóng vai "khung điều khiển" (harness) cho AI coding agent như Claude Code, Codex hay Cursor. Công cụ quét code tìm lỗi cơ học, nhờ chính agent của bạn chấm điểm chủ quan về thiết kế, rồi đưa agent vào vòng lặp next → sửa → resolve → next cho đến khi đạt điểm mục tiêu. Nó không phải SaaS và không có web dashboard.

Giải quyết gì

Code "vibe coding" do AI viết chạy được nhưng mục dần: file khổng lồ, abstraction lệch, mỗi chỗ xử lý lỗi một kiểu. desloppify biến chất lượng thành một con số 0–100 có cơ chế chống gian lận và lưu state qua nhiều phiên, để agent cày dần.

Có cần setup?

Có Cần Python ≥ 3.11, chạy pip install "desloppify[full]", chạy trong repo, rồi nạp skill vào agent. Công cụ không tự gọi API LLM: phần review chủ quan chạy bằng agent hoặc subagent của bạn, tức là tốn token của bạn.

Sức mạnh đã đo
  • Scan nhanh: 5 giây cho 4.7k dòng Python, 9 giây cho 65 file TS.
  • Độ chính xác cơ học khoảng 65–78%.
  • Bỏ sót 37 lỗi escape thật trong script Python.
  • Có bug: detector security bỏ qua exclude, sinh 2575 issue rác.
  • Phần review chủ quan (75% điểm) cần khoảng 20 subagent cho mỗi vòng; mình chưa chạy.

2. Cách hoạt động

scanKhoảng 17 detector cơ học
→
score25% cơ học + 75% chủ quan
→
review20 subagent LLM chấm 20 chiều
→
triageobserve → reflect → organize → enrich
→
executenext → sửa → resolve
→
rescanXác minh rồi lặp lại

State lưu trong .desloppify/ (state, plan, query), nên tiến độ được giữ qua nhiều phiên làm việc.

Hai nhóm điểm

  • Cơ học (25%): File health, Code quality, Duplication, Test health, Security. Mỗi chiều tính bằng (potential − failures) / potential; chiều nào có dưới 200 lượt kiểm tra thì bị giảm trọng số.
  • Chủ quan (75%): khoảng 20 chiều như High/Mid/Low elegance, Contracts, Type safety, Design coherence… LLM chấm trên một "blind packet", tức gói dữ liệu không chứa điểm cũ để reviewer không bị neo vào kết quả trước.

Bốn loại điểm và chống gian lận

  • overall: điểm tổng, bản dễ dãi.
  • strict: tính cả các issue bị đánh wontfix là nợ. Đây là "north star".
  • objective: chỉ tính phần cơ học. verified: chỉ cộng điểm cho fix đã được scan xác minh.
  • Chống gian lận: resolve phải kèm attestation, review lại có thể làm điểm giảm, điểm khớp đúng target thì bị reset.

3. Setup: cần gì, tốn gì

Bắt buộc có Python ≥ 3.11 và pip install "desloppify[full]". Gói [full] kéo theo tree-sitter, bandit, Pillow, PyYAML và defusedxml; venv thử nghiệm nặng 68 MB. Lệnh desloppify update-skill claude (hoặc setup để cài global) ghi skill/workflow guide vào cấu hình agent.

Công thức chạy an toàn trên Windows (PowerShell 5.1)

# 1. Dùng lại venv đã cài và đã kiểm chứng (nằm ngoài path sẽ scan, vì detector security bỏ qua exclude)
#    Đưa Scripts lên đầu PATH để bandit được thấy, không cần Activate.ps1 (tránh lỗi execution policy)
$env:PATH = "D:\học\advance-be\labs\desloppify-trial\py-env\Scripts;$env:PATH"
$env:PYTHONUTF8 = "1"; $env:PYTHONIOENCODING = "utf-8"

# 2. Chạy trong repo; mỗi --path là MỘT project mạch lạc
cd D:\học\advance-be\omnipos-finledger-hub
Add-Content .gitignore ".desloppify/"   # đừng dùng echo >> : PowerShell 5.1 ghi UTF-16, git không đọc được
desloppify --lang typescript scan --path apps/api --no-badge
desloppify status            # dashboard
desloppify show smells       # xem chi tiết theo detector
Chưa kiểm chứng: lần thử chỉ chạy trên bản copy không có node_modules và tsc. Chạy trên hub thật (đã npm install) có thể ra số khác.
Chi phí thật nằm ở review chủ quan.
  • review --run-batches --dry-run sinh ra 20 file prompt (tổng khoảng 152 KB), mỗi chiều cần một subagent.
  • Mỗi subagent còn tự đọc code. Ước lượng thô cho codebase cỡ 5k dòng là vài trăm nghìn đến khoảng 1 triệu token mỗi vòng; con số này chưa đo.
  • Nếu bỏ qua review, overall/strict bị kẹt ở mức ≤ 25.

4.1 Lần 1: scan root advance-be thất bại, nhưng lộ bug

Nhận xét riêng cho hub TS

  • Code sạch theo các detector đã thực sự chạy. Finding chủ yếu ở mức thấp.
  • Có ích Chuỗi http://localhost:3100 lặp ở 3 chỗ: env.schema.ts:20 đã có default, nhưng main.ts:43 và origin-check.guard.ts:28 lại thêm fallback ?? thừa. Tool gắn nhãn là "hardcoded URL", nhưng giá trị thật là gợi ý gom về một chỗ (DRY).
  • Nhiễu prisma.config.ts bị báo orphaned, dù đây là config do Prisma CLI đọc. Filter/interceptor global bị báo "single-use", dù đăng ký trong main.ts là cách làm chuẩn của NestJS.
  • Bug nhãn Log ghi "274 production files" trong khi zone thực tế chỉ có 56. Trùng với issue #921 và #936.
  • Lỗ hổng âm thầm Máy không có tsc và bản copy không có node_modules, vậy mà bước "Unused (tsc)" vẫn báo 0 instances, không cảnh báo gì (Python thì có cảnh báo khi thiếu bandit).

Mâu thuẫn ngay trong tài liệu của dự án

  1. docs/scoring.md viết "chưa review thì điểm 100% cơ học". CLI thực tế lại tính phần chủ quan bằng 0, nên overall = 0.25 × objective (43.2 × 0.25 = 10.8 và 75.8 × 0.25 ≈ 18.9, đúng với số đo).
  2. docs/CLAUDE.md dặn gom thành 3–4 batch theo chủ đề. CLI lại nói "do NOT regroup, launch 20 subagents in parallel". Còn docs/SKILL.md khuyên chạy 3–5 subagent mỗi đợt vì 20+ có thể cạn quota.

5. Điểm mạnh, điểm yếu, rủi ro

Mạnh

  • Ý tưởng đúng: một con số có chống gian lận, state lưu qua nhiều phiên.
  • Scan cơ học nhanh, đa ngôn ngữ, có chế độ CI (--profile ci, status --json).
  • Review thiết kế cẩn thận: blind packet, persona luân phiên, attestation.
  • Miễn phí cho cá nhân và dùng nội bộ.

Yếu

  • Precision 65–78%, nên agent mất công "sửa" cả false positive, thậm chí có thể xóa script đang dùng. Trong khi đó lại bỏ sót 37 lỗi escape thật.
  • 75% điểm phụ thuộc vào LLM review: tốn token và không tái lập được tuyệt đối.
  • Main đứng yên từ tháng 5, một người duy trì.
  • Bug gặp trên Windows: exclude bị bỏ qua, preflight bandit sai, nhãn đếm sai. Ngoài ra có issue riêng cho Windows: #909, #917, #918.

Rủi ro

  • Output chứa khối INSTRUCTIONS FOR LLM và hộp "No need to reply, just continue", được thiết kế để lái agent chạy liên tục. Ở chế độ bypass permissions, agent có thể đốt token rất lâu.
  • docs/SKILL.md mục 4 dặn agent: khi thấy tool sai thì clone repo upstream, sửa, push và mở PR/issue công khai. Repro có thể chứa code hoặc đường dẫn của bạn.
  • setup ghi skill vào cấu hình agent ở mức global.

Nhiều issue gần đây có đúng template "Problem / Fix / Minimal reproduction", khớp với hành vi tự mở issue ở trên, nhưng chưa chứng minh được là do agent viết. Chưa tìm thấy đánh giá độc lập nào trên HN, Reddit hay X: mọi tuyên bố kiểu "trên 98 điểm là code đẹp" mới chỉ là tuyên bố của tác giả.

6. Khuyến nghị và bước tiếp theo

Không cần setup để học tiếp lộ trình advance-be. Nếu muốn khai thác, chỉ lấy phần scan cơ học làm checklist, tự đọc kết quả và tự quyết sửa gì. Cách này hợp với nguyên tắc "Đạt tự làm, AI phản biện".
  1. Sửa 37 lỗi escape[15 phút]
    Literal nào không cố ý dùng \n thì thêm tiền tố r"..."; literal có \n cố ý thì nhân đôi \\ ở các chỗ còn lại. Sửa xong chạy lại py -3.13 -I labs/desloppify-trial/check-silent-escapes.py <6 file> để kiểm tra output rỗng.
  2. Gom http://localhost:3100[10 phút]
    Dùng env.schema.ts làm nguồn duy nhất và bỏ 2 fallback ?? thừa trong hub.
  3. Scan hub thật[15 phút, tùy chọn]
    Chạy trên hub đã npm install theo công thức ở mục 3 để có số liệu tsc và dead export chính xác.
  4. Thử review chủ quan cho 1–3 chiều[chỉ khi chấp nhận tốn token]
    Dùng review --prepare --dimensions high_level_elegance,… với ít subagent, xem nhận xét có đáng tiền không. Chưa nên chạy đủ 20 chiều.
  5. Không làm
    Không chạy desloppify setup ở mức global, và không để agent tự chạy next/resolve vô hạn ở chế độ bypass permissions.

8. Câu hỏi chưa giải quyết

  1. Chất lượng của review chủ quan (75% điểm) chưa được kiểm chứng vì chưa chạy vòng subagent nào. Chưa biết nó có bắt được vấn đề lớn nhất của các script Python không (dữ liệu nội dung hardcode hàng trăm dòng trong code).

  3. Bug exclude của security chỉ xảy ra trên Windows hay ở mọi nền tảng? Cả cờ --exclude lẫn config đều bị bỏ qua, nhưng chưa có máy Linux/macOS để so sánh.
