## 4. Content scope (settled)

The guide covers all 46 slides (title pages get a null chip) and these blocks the slides only touch:
1. **Why fast, measured**: single-threaded command execution proven (a slow command such as a big `SORT`/`KEYS *`/Lua busy loop/`DEBUG SLEEP` in client A blocks a `PING` in client B — latency recorded), round trips vs pipelining (`redis-benchmark` with and without `-P`, and MGET vs N GETs), `INFO`/`LATENCY`/`SLOWLOG`.
2. **Storage internals**: encodings (`OBJECT ENCODING`: int/embstr/raw, listpack → hashtable/skiplist conversion at `*-max-listpack-entries`), `MEMORY USAGE`, answer to slide 30 (Hash vs String JSON) with measured bytes and the commands for C1/C2/C3 (HGET / HINCRBY / HGETALL vs GET + parse + SET whole JSON with a lost-update race).
3. **Expiry and eviction**: expire dictionary, passive vs active expiry observed (`expired_keys`, `INFO keyspace` expires count dropping without access), `maxmemory` + each eviction policy observed on a small limit (`noeviction` → OOM error; `allkeys-lru`/`volatile-ttl`/`allkeys-lfu` → which keys survive), TTL jitter link to lesson 02.
4. **Persistence**: RDB (`BGSAVE`, `LASTSAVE`, fork in `INFO persistence`), AOF (`appendonly yes`, `appendfsync everysec`), hybrid `aof-use-rdb-preamble`, a restart test showing what survives with each mode (data loss window). Note this machine's container starts with `--appendonly no` and the default `save` schedule.
5. **Data structures in practice**: String counters (`INCR`), List queue (`LPUSH/BRPOP`, two clients), Hash cart (slide 33 commands), Set (likes, `SINTER` common followers), ZSET leaderboard (bridge to FR-M2-04 best-sellers), delay task with ZSET (slide 37: `ZADD` score = due time, poller with `ZRANGEBYSCORE` + atomic claim via `ZREM`/Lua so two pollers do not both take the same job), big keys (`--bigkeys`/`MEMORY USAGE`/`SCAN`, `DEL` vs `UNLINK` latency on a 1M-element key, `lazyfree-lazy-user-del`), hashtags and hash slots (`CLUSTER KEYSLOT` and `CROSSSLOT` error need a cluster-enabled instance).
6. **Architecture**: master-replica async replication lag / stale read, Sentinel failover, Cluster 16384 slots — at least a measured replica demo (second container `REPLICAOF`, `INFO replication`, `WAIT`), and slot computation; full Sentinel/Cluster may be optional or diagram-only with honest labelling.
7. **Distributed lock (capstone, slide 40 + homework 43)**: builds on lesson 02's `SET NX PX` + compare-and-delete. Shows the failures: plain `DEL` releasing someone else's lock after TTL expiry, lock expiring while work continues (GC pause), why fencing tokens are needed (link lesson 14 optimistic `version` / conditional UPDATE in Postgres), Redlock caveat in one honest paragraph. Homework seat `A34_S012C` on flight `FA634` with 2 concurrent requests and a self-check.
8. **Bridge to OmniPOS M2 and Boss Challenge 2**: idempotency key on Redis (`SET NX EX` + stored response), Lua token bucket (atomic `EVAL`), cache-aside menu — at least one worked Lua script measured; how this maps to FR-M2-02/04/05 and the `quan-ly-hop-dong` targets. A Node/NestJS driver drill (node-redis or ioredis, pick one with reason) reviewing an AI-written snippet with seeded mistakes (KEYS in hot path, no TTL, lock released with DEL, GET-then-SET race instead of INCR/Lua, big HGETALL, no pipelining, no error/offline-queue handling).

The slides are partly outdated; the guide must say what Redis 7.2 actually does (e.g. Redis 6 I/O threads are off by default — `io_threads_active:0` here; expiry in Redis 7 no longer uses a ZSET; `noeviction` default; `UNLINK`/lazyfree) with a measurement, using verdict chips `Đúng trên Redis 7.2` / `Đúng một phần` / `Cần sửa` (or equivalent the plan defines).
