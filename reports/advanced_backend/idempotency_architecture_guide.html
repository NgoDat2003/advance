Toàn Cảnh 4 Kịch Bản Xử Lý Tại Cửa Ngõ Backend

1
Frontend Gửi Lên Header: x-idempotency-key + Body JSON
Frontend tự sinh mã UUID theo Form hoặc gắn ID nghiệp vụ (ví dụ: addendum:HD149:PL02). Frontend KHÔNG kết nối Redis!
2
Backend Interceptor: Validate Cú Pháp & Tính SHA-256 Body
Nếu body sai cú pháp -> Trả ngay 400 Bad Request. Nếu đúng -> Băm chuỗi Body thành mã Hash SHA-256 để chống giả mạo payload.
3
Tra Cứu Key Trong Redis / Database Table
• Chưa có key: Ghi nhận status = 'PENDING', khóa tạm 60 giây, cho phép chạy tiếp vào Service.
• Key đang PENDING: Trả về ngay 409 Conflict (Chặn đứng thao tác bấm đúp liên thanh).
• Key đã COMPLETED: So khớp Hash Body. Nếu trùng 100% -> Bốc luôn kết quả cũ trả về 200 OK trong 1ms (Không chạy lại Service). Nếu khác Body -> Báo 422 Unprocessable Entity.
4
Chạy Service Nghiệp Vụ & Giao Dịch Database
Mở Transaction: Ghi bảng hợp đồng, trừ tiền cọc, sync SAP...
5
Cập Nhật Trạng Thái & Thiết Lập Hạn Sử Dụng (TTL)
• Thành công: Đổi sang COMPLETED, lưu kèm Response Body, đặt TTL = 24 giờ. Trả về 201 Created.
• Thất bại (Catch Error): Xóa ngay key (DEL key) để user sửa dữ liệu và bấm lại được.

Quy Tắc Vàng: Khi Nào Được Xóa Redis, Khi Nào Không?

Tình huống giao dịch Trạng thái trong Redis Hành vi xử lý đối với Redis Lý do kỹ thuật
1. Thanh toán THÀNH CÔNG COMPLETED TUYỆT ĐỐI KHÔNG XÓA NGAY! Giữ lại kèm TTL 24 giờ. Nếu xóa ngay, khi mạng lag gửi lại request lần 2, hệ thống sẽ trừ tiền thêm 1 lần nữa! Hết 24h Redis tự bốc hơi.
2. Lỗi nghiệp vụ có thể sửa (Thiếu tiền, sai mã) FAILED XÓA NGAY LẬP TỨC (`DEL key`) Để người dùng nạp thêm tiền hoặc sửa lại mã giảm giá rồi bấm thanh toán lại thì không bị chặn!
3. Server bị sập nguồn / Crash giữa chừng PENDING ĐỂ TỰ HẾT HẠN (TTL 60s) Sau 60 giây cái khóa PENDING tự động mở ra, tài khoản của khách không bị đóng băng vĩnh viễn.
4. Admin / Kế toán chủ động hủy giao dịch Bất kỳ Chủ động gọi `DEL key` Xóa sạch dấu vết phiên cũ để tạo phiên giao dịch mới từ đầu.

So Sánh Trực Diện: Redis vs Bảng Database Riêng (PostgreSQL)

Tiêu chí so sánh Dùng In-Memory REDIS Dùng BẢNG DATABASE (PostgreSQL)
Tốc độ đọc/ghi Siêu nhanh (0.1 - 0.5 ms) trên RAM 5 - 20 ms trên đĩa SSD
Tính toàn vẹn (ACID Transaction) Không bọc chung Transaction với bảng Hợp đồng Maycha được Có thể bọc chung trong 1 DB Transaction (Lỗi hợp đồng -> Tự rollback key)
Cơ chế dọn rác (Cleanup) Tự động 100% bằng TTL (60s hoặc 24h) Phải viết thêm Cron Job dọn dẹp các key quá 30 ngày
Tính bền vững khi cúp điện Có nguy cơ mất dữ liệu nếu Redis chưa kịp sync đĩa Bền vững 100% (WAL log), không bao giờ mất
Hệ thống phù hợp Sàn TMĐT, Flash Sale, API công cộng nhiều người bấm Hệ thống ERP, Tài chính, Bán lẻ Maycha

Code Mẫu Triển Khai Chuẩn

1. Phía Backend: NestJS Interceptor

@Injectable()
export class IdempotencyInterceptor implements NestInterceptor {
  constructor(private readonly redis: RedisService) {}

  async intercept(context: ExecutionContext, next: CallHandler): Promise<Observable<any>> {
    const req = context.switchToHttp().getRequest();
    const key = req.headers['x-idempotency-key'];
    if (!key) return next.handle(); // Không có header thì bỏ qua

    const redisKey = `idemp:${key}`;
    const bodyHash = crypto.createHash('sha256').update(JSON.stringify(req.body)).digest('hex');

    // 1. Thử khóa key với trạng thái PENDING (TTL = 60s)
    const acquired = await this.redis.set(redisKey, 'PENDING', 'NX', 'EX', 60);

    if (!acquired) {
      const cached = await this.redis.get(`${redisKey}:response`);
      if (cached) {
        const { savedHash, body } = JSON.parse(cached);
        // Kiểm tra Hash Body
        if (savedHash !== bodyHash) {
          throw new UnprocessableEntityException('Cùng Idempotency Key nhưng nội dung Body bị thay đổi!');
        }
        return of(body); // Trả kết quả cũ 200 OK
      }
      throw new ConflictException('Yêu cầu đang được xử lý, vui lòng chờ!');
    }

    // 2. Chạy Service
    return next.handle().pipe(
      tap(async (responseBody) => {
        // [THÀNH CÔNG]: Lưu kết quả và đặt TTL 24h (86400s)
        await this.redis.set(`${redisKey}:response`, JSON.stringify({ savedHash: bodyHash, body: responseBody }), 'EX', 86400);
        await this.redis.set(redisKey, 'COMPLETED', 'EX', 86400);
      }),
      catchError(async (err) => {
        // [LỖI]: Xóa key ngay để user thử lại!
        await this.redis.del(redisKey);
        throw err;
      })
    );
  }
}
