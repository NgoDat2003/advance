Nhắc nhanh Bài 14

Bài này dùng lại 3 thứ của Bài 14, nên nếu bạn chưa học xong chặng 3–5 bên đó cũng không sao, chỉ cần nhớ:

  • ALTER đổi cấu trúc (thêm cột, đổi kiểu) lấy AccessExclusiveLock, nên đứng sau một transaction quên đóng là cả bảng treo (Bài 14 chặng 3).
  • INSERT dòng con lấy FOR KEY SHARE trên dòng cha (chặng 2).
  • Khóa nhiều dòng thì khóa theo cùng một thứ tự (ORDER BY id FOR UPDATE) để không có 40P01 (chặng 5). Lưới an toàn cuối cùng là CHECK, vi phạm thì ra 23514.

Nếu bạn đang để mở một transaction cũ trên DB (ví dụ demo chặng 3 Bài 14 còn "idle in transaction"), hãy COMMIT/ROLLBACK nó trước khi học chặng 4: transaction cũ làm CREATE INDEX CONCURRENTLY phải chờ, và index mới tạo có thể chưa được planner dùng.

Cách chạy một region trong DBX

Mỗi file chia thành nhiều region, mở bằng dòng -- #region tên · tiêu đề và đóng bằng -- #endregion. Bôi đen từ dòng mở tới dòng đóng → Run Selection. Tab để chế độ auto-commit; các chỗ cần transaction đã có sẵn BEGIN … COMMIT/ROLLBACK trong SQL.

  • Dòng đầu mỗi region là SET search_path = lab07_modeling;. Lý do: DB của bạn đặt mặc định search_path = lab03_indexing, public (kiểm tra C08), thiếu dòng này thì bảng sẽ bị tạo nhầm sang schema của Bài 3.
  • DBX dừng ở câu lỗi đầu tiên (đã thử trên máy bạn). Vì vậy câu lỗi cố ý đặt cuối region, hoặc nằm trong BEGIN … ROLLBACK để các câu sau vẫn có nghĩa khi chạy bằng psql. Nếu một region dừng ở lỗi khi đang trong BEGIN, chạy riêng ROLLBACK; rồi mới chạy region tiếp.
  • Region của file *.A.sql chạy ở tab ADVANCE_BE_LAB, file *.B.sql ở tab ADVANCE_BE_LAB_B. Chạy A trước, trong lúc A đang pg_sleep thì chạy B.
