Thêm cột, JSON, thêm index khi bảng đang chạy

Mục tiêu: đo xem câu ALTER TABLE nào làm PG viết lại cả bảng 500.000 dòng, câu nào chỉ mất 1 ms, và tạo index mà không chặn người đang ghi.

LÀ GÌ?
Đổi cấu trúc bảng (thêm cột, đổi kiểu, thêm index) trong lúc app vẫn đọc ghi.
TẠI SAO?
ALTER đổi cấu trúc (thêm/xóa cột, đổi kiểu) lấy khóa mạnh nhất. Nếu nó phải viết lại bảng, khóa giữ lâu và API treo. (Vài ALTER nhẹ như SET (fillfactor) lấy khóa yếu hơn.)
KHI NÀO KHÔNG?
Đừng tạo sẵn cột dự phòng extra1, extra2 "cho sau này". Trên PG 11+ thêm cột chỉ mất vài ms.

Slide 13 chỉ là tiêu đề phần "Table Format". Bảng thí nghiệm là ddl_contracts: bản sao 500000 hợp đồng của Bài 3. Mở 04-table-format.sql trong DBX, bôi đen từng region rồi Run Selection.

-- #region add-column · Thêm cột trên bảng 500.000 dòng: khi nào PG phải viết lại cả bảng? (slide 14, 17)
SET search_path = lab07_modeling;  -- DB mặc định trỏ vào lab03_indexing
SET statement_timeout = '60s'; SET lock_timeout = '5s';
DROP TABLE IF EXISTS ddl_contracts, ddl_events;
CREATE TABLE ddl_contracts AS SELECT * FROM lab03_indexing.hw_contracts;
ALTER TABLE ddl_contracts ADD PRIMARY KEY (id);
-- ddl_events ghi lại "filenode" (tên file vật lý của bảng) sau mỗi bước. Filenode đổi = PG đã viết lại toàn bộ bảng.
CREATE TABLE ddl_events (id int GENERATED ALWAYS AS IDENTITY, buoc text, filenode oid);
INSERT INTO ddl_events (buoc, filenode) VALUES ('ban đầu', pg_relation_filenode('ddl_contracts'));
ALTER TABLE ddl_contracts ADD COLUMN note text;                                   -- cho phép NULL
INSERT INTO ddl_events (buoc, filenode) VALUES ('ADD note text', pg_relation_filenode('ddl_contracts'));
ALTER TABLE ddl_contracts ADD COLUMN version int NOT NULL DEFAULT 0;              -- default hằng số
INSERT INTO ddl_events (buoc, filenode) VALUES ('ADD version DEFAULT 0', pg_relation_filenode('ddl_contracts'));
ALTER TABLE ddl_contracts ADD COLUMN created_at timestamptz NOT NULL DEFAULT now(); -- now() tính MỘT lần cho cả bảng
INSERT INTO ddl_events (buoc, filenode) VALUES ('ADD created_at DEFAULT now()', pg_relation_filenode('ddl_contracts'));
ALTER TABLE ddl_contracts ADD COLUMN rnd float8 DEFAULT random();                 -- default "volatile": mỗi dòng một giá trị
INSERT INTO ddl_events (buoc, filenode) VALUES ('ADD rnd DEFAULT random()', pg_relation_filenode('ddl_contracts'));
ALTER TABLE ddl_contracts ALTER COLUMN customer_id TYPE bigint;                    -- đổi kiểu int → bigint
INSERT INTO ddl_events (buoc, filenode) VALUES ('customer_id int → bigint', pg_relation_filenode('ddl_contracts'));
SELECT buoc, filenode, filenode <> lag(filenode) OVER (ORDER BY id) AS rewrite FROM ddl_events ORDER BY id;
SELECT count(DISTINCT created_at) AS so_gia_tri_created_at, count(DISTINCT rnd) AS so_gia_tri_rnd FROM ddl_contracts;
-- #endregion

Thời gian từng câu ALTER nằm trong W4 bên dưới.

Làm mẫu · đọc filenode để biết PG có viết lại bảng không
  1. Filenode là tên file vật lý của bảng trên đĩa. PG viết lại bảng = tạo file mới = filenode đổi. Bảng ddl_events ghi filenode sau mỗi bước.
  2. Ba câu đầu giữ nguyên 34014. PG chỉ ghi giá trị mặc định vào catalog; dòng cũ đọc ra thì PG tự điền. Vì vậy chỉ mất khoảng 1.140 ms (psql in dấu chấm là phần thập phân: một phần nghìn giây, không phải một nghìn).
  3. now() được tính một lần cho cả câu lệnh: cả bảng có đúng 1 giá trị created_at. Nên nó vẫn là "hằng số" với PG.
  4. random() cho mỗi dòng một giá trị khác nhau (500000 giá trị). PG phải ghi từng dòng: filenode thành 34030, mất 527.308 ms.
  5. Đổi int → bigint làm mỗi dòng dài thêm 4 byte, cũng phải viết lại: 34036, 518.812 ms.

Quy tắc rút ra: thêm cột cho phép NULL hoặc có default không đổi theo dòng thì rẻ. Default "volatile" (random(), gen_random_uuid()) và đổi kiểu thì đắt, tỉ lệ thuận với số dòng.

-- #region json · Cột jsonb và hai cách đánh index cho trường bên trong JSON (slide 15–16)
SET search_path = lab07_modeling;  -- DB mặc định trỏ vào lab03_indexing
SET statement_timeout = '60s'; SET lock_timeout = '5s';
ALTER TABLE ddl_contracts ADD COLUMN IF NOT EXISTS data jsonb;
DROP INDEX IF EXISTS ddl_contracts_channel_idx, ddl_contracts_data_gin;
-- 1% hợp đồng ký qua kênh WEB, 0,1% là khách VIP.
UPDATE ddl_contracts SET data = jsonb_build_object('channel', CASE WHEN id % 100 = 0 THEN 'WEB' ELSE 'POS' END, 'vip', id % 1000 = 0);
ANALYZE ddl_contracts;
EXPLAIN (ANALYZE, COSTS OFF) SELECT count(*) FROM ddl_contracts WHERE data->>'channel' = 'WEB';
-- Cách 1: index biểu thức trên đúng một trường.
CREATE INDEX ddl_contracts_channel_idx ON ddl_contracts ((data->>'channel'));
ANALYZE ddl_contracts;
EXPLAIN (ANALYZE, COSTS OFF) SELECT count(*) FROM ddl_contracts WHERE data->>'channel' = 'WEB';
-- Cách 2: GIN trên cả cột, phục vụ toán tử chứa @> cho mọi khóa.
CREATE INDEX ddl_contracts_data_gin ON ddl_contracts USING gin (data jsonb_path_ops);
EXPLAIN (ANALYZE, COSTS OFF) SELECT count(*) FROM ddl_contracts WHERE data @> '{"vip": true}';
-- #endregion

Slide 18 · MySQL đúng, PG khác
Slide nói

Trước MySQL 5.6 thêm index khóa cả bảng; dùng pt-online-schema-change hoặc ALGORITHM=INPLACE, LOCK=NONE.

PG 16 đo được

CREATE INDEX giữ ShareLock: người đọc vẫn đọc, người ghi bị chặn (55P03 sau 2000.334 ms). CONCURRENTLY giữ ShareUpdateExclusiveLock: người ghi vẫn ghi. Cái giá: nó chờ mọi transaction ghi đang mở, và không chạy được trong BEGIN (25001).

Hai phiên: index thường và CONCURRENTLY (tùy chọn, 10 phút)

Tab A = kết nối ADVANCE_BE_LAB, tab B = ADVANCE_BE_LAB_B. Cả hai tab ở chế độ auto-commit. Nếu tab B đang ở Manual Commit (Tx: [M]), DBX bọc câu lệnh trong transaction và CONCURRENTLY báo 25001. Mỗi lượt A ngủ 6 giây; trong 6 giây đó chạy region cùng tên ở tab B.

-- #region cic · B tạo index CONCURRENTLY trong lúc A đang ghi

Đề: tạo bảng my_c4_stores 100.000 dòng (id, code) không có cột data. Đặt lock_timeout 2 giây, thêm cột data jsonb NOT NULL DEFAULT '{}', ghi quận vào data (2% là Q7), tạo index biểu thức trên data->>'district', rồi dán EXPLAIN vào ô dưới.

SELECT pg_relation_filenode('my_c4_stores');            -- phải giống số trên
UPDATE my_c4_stores SET data = jsonb_build_object('district', CASE WHEN id % 50 = 0 THEN 'Q7' ELSE 'Q1' END);
